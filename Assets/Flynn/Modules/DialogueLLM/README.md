# DialogueLLM — LLM-driven NPC dialogue

An NPC you can type at, who answers in character, remembers you, and whose answers put real
entries in the player's Field Guide.

Assembly `Flynn.Npc` → depends on `Flynn.Base`, `Flynn.Contracts`, `Flynn.Modules.Dialogue`, TMP.
Nothing in the game depends *on* this module, so it can be deleted by removing the folder.

## Start here

Open **`Scenes/Community_Demo.unity`** and press Play.

- **1** / **2** — talk to Maren or Bode
- type, **Enter** to send, **Esc** to leave
- **Y** — open the Field Guide

Ask about the spring, the mast, the bees, the kiln — or about each other. Things you are actually
told appear in the Field Guide as you learn them.

There is one island (`mosslight_clearing.json`) and one scene, on purpose — the module is easier
to read with a single worked example than with several half-built ones.

### Setting the API key

`Flynn > AI > OpenRouter Settings`, or the env var `OPENROUTER_API_KEY`. **No key is stored in
any asset.** Without one the NPCs fall back to their scripted `fallbackReply` lines and everything
else still runs. Optional: a local Ollama at `localhost:11434` for embeddings — without it, recall
degrades to keyword matching rather than failing.

## How a turn works

```
player types
   ↓
DialogueManager          builds the prompt: island content + this NPC + recalled memories
   ↓
SceneLlmManager          OpenRouter or a local model
   ↓
NpcReplyEnvelope         structured JSON, not prose
   ↓  reply ─────────→ LlmCozyDialogueBridge ──→ FieldDialogue (the cozy box you see)
   ↓  memory_updates ─→ NpcMemoryDatabase (LiteDB + vectors)
   ↓  trust/affection ─→ NpcRelationshipState
   └  triggers_fired ─→ DialogueTriggerChannel ──→ LlmKnowledgeRelay ──→ KnowledgeBase
                                                                          ↓
                                                                     Field Guide
```

The model returns `reply`, `topic`, `intent`, `tone`, `mood_shift`, `flags[]`,
`suggested_player_replies[]` (+ parallel `suggested_reply_verbs[]`: ask / press / joke / show),
`triggers_fired[]`, relationship deltas, and `memory_updates` tagged player / self / world.

## The part worth understanding: how learning reaches the Field Guide

**Signal ids and topic ids are the same string.** A signal in the island JSON — `learn.spring` —
is also a topic id in `Configs/MosslightTopics.asset`.

When the model claims a signal fired, `DialogueManager` checks it against the island's signal
allowlist for that turn *before* raising it. `LlmKnowledgeRelay` then hears the raised signal and
calls `KnowledgeBase.Discover(id)`.

That ordering is the safety property: **a hallucinated topic cannot reach the archive**, because
the model can only fire ids the island file declares. The relay filters on `handler: "Discover"`
so story beats and one-off effects don't become archive entries.

`MosslightTopics.asset` is generated by `Editor/BuildCommunityScene.cs` rather than hand-authored,
so the two id lists cannot drift apart.

## Authoring a community

One JSON file per island (`Configs/Islands/`, schema at `Islands/island.schema.json`).

| Section | What it does |
|---|---|
| `community` | Shared overview, current situation, mood, culture. Every NPC sees this. |
| `things` | World objects with `aliases` — how the model recognises what the player means. |
| `signals` | What may fire. `minTrustToFire` gates them. `handler: "Discover"` = a Field Guide entry. |
| `npcs` | Voice (`speakingStyle`, `doRules`, `dontRules`) and `knowledge[]`. |

Knowledge entries carry a `kind` — `fact`, `belief`, `rumor`, `secret`, `avoid` — and a
`revealTrustThreshold`. `avoid` is the useful one: it tells an NPC to deflect a topic and point
elsewhere, rather than pretending ignorance.

**`mosslight_clearing.json` demonstrates the whole feature set:**

- **Maren** — herbalist. Knows the spring, the bees, the herbs.
- **Bode** — salvager. Knows the mast, the kiln, tools.
- **Cross-knowledge in both directions.** Maren knows *of* the mast and kiln but sends you to Bode
  for the detail; Bode defers all botany to Maren. Each speaks about the other by name.
- **A shared observation from two angles.** Maren believes the spring has run warmer since the mast
  went quiet (revealed at trust 25). Bode publicly says she's imagining it — and admits he has
  started measuring it (trust 15).
- **A trust-gated secret.** Bode silenced the mast himself. Gated at trust 45, and Maren genuinely
  does not know, so she cannot leak it.

## Things that will bite

- **The brain needs a `UIDocument` even when its own panel is hidden.** `TryBindUi` hard-fails
  without one. The demo scenes give it a UIDocument with *no* source asset: the root exists, the
  named lookups all miss, and it builds a fallback panel in C# which `_hideOwnPanel` then hides.
- **`_hideOwnPanel` hides inline, not via the `.hidden` class**, because that class lives in a
  stylesheet this repo doesn't ship. Relying on the class left an unstyled panel covering the UI.
- **A `PanelSettings` needs a `PanelTextSettings` at runtime.** The Editor supplies a default;
  the player does not. Without it every font resolves null, `-unity-font-definition` overrides the
  panel default with that null, and all text silently vanishes while layout collapses to zero size.
  `UI/FieldTextSettings.asset` exists for this reason.
- **Cozy components take the KnowledgeBase through a field called `knowledge`**, and it ships
  unassigned on the prefab. Unassigned means the Field Guide throws on open. The scene builder
  assigns it to every component that has the field.
- **`Flynn.Npc.Editor` is `autoReferenced: false`**, so dynamically compiled scripts can't see its
  types. Reach them by reflection.

## Not done

- No conversation has been run end-to-end against a live model here. The wiring is verified and
  the UI renders; the first real exchange is still unproven.
- `PlayerCodex` captures *all* `memory_updates` with no quality gate — a known issue, see
  `NPC_Memory.md`.
- No memory store ships with the module; `NpcMemoryDatabase` creates one on first run
  (`saveSlotId`, default `slot_0`). Delete that asset any time you want a clean slate — the NPCs
  will have forgotten you.
